# Write a scenario

1. Choose the lowest unit that contains every unit the story names; a hop to a need of the root belongs to the root.
2. Under `scenarios` in its manifest, from [unifold.template.yaml](../assets/unifold.template.yaml): `summary`, `source`, `given`, `hops`, `expect`. A hop is `caller -> target.part(input): result`: units by their path from the holding unit, a capability or need of the holding unit bare. The result is required and is text: quote a number (`"1000"`). Write `ok`, an error case spelled as the contract names it, a value, or `= <case>` to take the input and the result of an example of the part. Every part must be a command, query, event or callback of the contract of the connection the hop uses; where two connections share the part, write `target.capability.part`. Write a hop as the call happens: the consumer calls a command or query, the provider raises an event or calls a callback. Steps that run at the same time go under `parallel`, a step that runs again and again under `repeat`, and a story that a child already tells is included as `child.scenario`, or `caller -> child.scenario` where the child's capability has several users at this level. Read the result with `unifold scenario UNIT NAME`, and with `--expand` for every level. 
3. Where the path starts in another state than the start state of a contract, set it under `given`: `unit.capability: state`. A condition that no contract declares is a sentence there.
4. Run `check`. A hop that does not resolve means a missing connection, a missing part or a wrong cut: fix the manifests or the contract, never the story. A hop that the states of its connection do not allow means a wrong result, a missing `given`, or a gap in `## States`.
5. [Finish](../SKILL.md#4-finish). `unifold scenario UNIT NAME` draws the scenario.
